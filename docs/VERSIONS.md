# Version history

Newest first. The running version is shown at the bottom of the dashboard sidebar and in `GET /api/status`.

| Version | Date | Highlights |
|---|---|---|
| 0.13.4 | 2026-11-12 | **Chat/Telegram runs now have a live activity log**: chat and Telegram turns only saved step rows, so the run page's log (which reads the run event stream) was empty. They now publish the same events as agent runs (model calls, tool calls with results, finish). Runs recorded before this version stay empty in the log; their steps remain visible. |
| 0.13.3 | 2026-11-12 | Default **max images per run/chat turn** raised from 4 to 5. |
| 0.13.2 | 2026-11-12 | **Image cap fix**: when the model asked for more `generate_image` calls in one reply than the per-turn cap (default 4), every call in the batch was refused and nothing rendered. Now the first calls up to the cap render and only the extra ones are refused. |
| 0.13.1 | 2026-11-12 | **Active chat turns count as running**: a chat or Telegram turn in progress now shows in the sidebar Runs badge and the Overview "N running" tile (pulsing), like agent runs. |
| 0.13.0 | 2026-11-12 | **Telegram Agent gets everything**: all tools (terminal and file tools included) and all enabled skills, max steps 120 (an agent created by 0.11 is widened once). New Telegram menu commands: `/settings` (inline buttons for thinking, effort and max steps ±10/±50, saved on the agent), `/tools`, `/skills`. Telegram chat turns use the agent's thinking and effort. |
| 0.12.0 | 2026-11-12 | **Every chat turn is a run**: each dashboard chat turn and each Telegram message is recorded in Runs with the same details as scheduled runs (model calls and tool calls as steps, tokens, timings, result, stopped/failed). Runs has a new **Type** filter: Chat, Telegram chat, Agent (from chat), Agent (from Telegram), Scheduled, Manual, API (`GET /api/runs?trigger=`). Triggers: `chat_turn`, `telegram_turn` (new); `chat`, `telegram` (agent runs started from chat). |
| 0.11.0 | 2026-11-12 | **Telegram Agent**: tasks started from the Telegram bot now run under a dedicated general-purpose "Telegram Agent" (trigger `telegram`), so they show in Runs and can be filtered via the Agent dropdown. Its working folder `data/telegram_bot/` (gitignored with the rest of `data/`) has `images/`, `memory/` and `scratchnotes/`. |
| 0.10.1 | 2026-11-11 | **Notification fix**: Settings → Notifications card with an Enable button (permission is now requested from a click, not after async work), status diagnostics (denied / insecure origin / unsupported) and a test button; the notice also fires when the tab is hidden, not just unfocused. |
| 0.10.0 | 2026-11-11 | **Long-task notification**: when a chat reply takes 45 s or more and finishes (not stopped, no error), Atom shows a system notification if the tab is unfocused (permission requested on first send), otherwise an in-app toast. |
| 0.9.1 | 2026-11-11 | **Security hardening**: the API now refuses requests whose `Host` is not this machine (blocks DNS rebinding) and state-changing requests from another site's `Origin` (403). Extra hosts via `--host` or `ATOM_ALLOWED_HOSTS`. httpx request logging is pinned to WARNING so a Telegram bot token in a URL can never reach logs. |
| 0.9.0 | 2026-11-10 | **Image queue**: image renders from every source (chat tool, agents, Images page) and every image service now run one at a time, first come first served, so they no longer slow each other or push the machine into swap. `GET /api/status` has `images: {running, queued}`; the Images page shows "Queued behind another image…" while it waits. |
| 0.8.1 | 2026-11-10 | **Fixes**: leaving the Chat page no longer stops a running reply (only Stop does); the sidebar model light no longer flickers red on a single missed health probe (down is reported after 3 consecutive misses). |
| 0.8.0 | 2026-11-10 | **Per-agent state**: agents get a `set_state` tool (no approval, max 2000 chars) to leave a private note for their next run ("last status", "checked up to X"); it is injected at the top of every run and is viewable/editable/clearable in the agent's edit dialog. API: `GET/PUT/DELETE /api/agents/{id}/state`. Always available even when an agent's tool list is restricted. |
| 0.7.0 | 2026-11-10 | **`update_memory` agent tool**: a job can replace its own saved memory (e.g. a single "last status") by id instead of adding a near-duplicate every run; `remember` skips exact duplicates; memory ids are shown in the injected memories and in `recall`. **Agent memory scope now defaults to `agent`** everywhere (new agents, default agent, run config, DB schema). New approval kind `update_memory`. |
| 0.6.0 | 2026-11-10 | **Artifact previews in chat**: images the assistant creates or mentions appear as inline thumbnails under the reply (click for full size); PDFs, text, Markdown, JSON and CSV files appear as expandable preview cards. |
| 0.5.2 | 2026-11-10 | **Stale UI fix**: the page (`index.html`) is now served with `Cache-Control: no-cache` and hashed assets as immutable, so a browser can no longer keep an old build (missing Copy / Run again / timestamps) after an update. |
| 0.5.1 | 2026-11-10 | **Model switcher can stop servers started from a terminal** (ops/start.sh or by hand): Atom finds the llama-server on the profile's port and stops it, so every running model shows a Stop button. |
| 0.5.0 | 2026-11-10 | **Uncensored model profile**: huihui-ai abliterated Qwen3.8-27B (Q4_K, :8082) selectable in the model switcher, per agent, and via `ops/llama-server.sh uncensored`. |
| 0.4.0 | 2026-11-10 | **Chat page**: every message shows its date and time; **Copy** on user and assistant messages; **Run again** re-sends the prompt a reply answered. Images page also shows date/time. |
| 0.3.0 | 2026-11-10 | Images page: **Copy prompt**, **Run again** (same settings, new random seed), **Retry** on failures, "Reuse settings" renamed **Edit in box**. LUSTIFY V10 (Krea 2) service and image-to-image. |
| 0.2.0 | 2026-11-09 | SDXL image service, Images page, sandboxed file tools, clickable file paths in chat, Z-Image generate_image tool. |
